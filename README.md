# BIZ: сайт и управление платформой

[Первый запуск lomviko.com](docs/PRODUCTION.md) · [Исправления и проверка 16 требований](docs/FIXES-2026-10-15.md) · [Лицензии зависимостей](docs/DEPENDENCIES.md)

Проверка всего проекта: `npm run check`. Архив после коммита: `npm run prepare:deployment`.

Репозиторий объединяет сайт, две браузерные админки и сервер CRM. Десктопное приложение находится отдельно: https://github.com/wwchugunov/CRM_BUES.

```text
ch_landing/     публичный сайт и загрузки
landing_admin/  админка сайта
orbit_admin/    API, лицензии, компании, почта, админка приложения
compose.yaml    запуск всех четырёх сервисов
deploy/        инструкции развёртывания
tools/         управление контейнерами и доступом
```

Из корня этого репозитория:

```sh
docker compose up -d --build
```

Нужен Docker с Compose. При первом запуске создаются постоянные тома `ch-platform_api-data` и `ch-platform_releases`. Имя проекта закреплено: существующие локальные данные и настройки сохраняются при переходе из общего рабочего каталога.

| Сервис | Адрес |
| --- | --- |
| Сайт | http://127.0.0.1:4546 |
| Админка сайта | http://127.0.0.1:4547 |
| Админка приложения | http://127.0.0.1:4548 |
| API | http://127.0.0.1:4545 |

Порты можно изменить через `.env`, взяв за основу `.env.example`. Текущие тестовые установщики используют API на порту 4545.

Для входа в обе админки нужны ключ администратора и одноразовый код:

```sh
sh tools/docker.sh credentials
sh tools/docker.sh code
```

Ключ записывается в `.runtime/admin-access.txt`. Один код используется для одного входа; для второй админки получите следующий. Пароли и ключи не хранятся в Git. Настройки SMTP задаются в админке приложения и сохраняются зашифрованными в томе API.

## Проверка полного цикла

1. Загрузите три установщика новой версии в админке сайта и опубликуйте версию.
2. Установите приложение, выберите регистрацию, введите имя, компанию, почту и пароль; подтвердите код из письма.
3. После подтверждения автоматически создаются владелец и компания с полным доступом на 14 дней. Загрузка файла сама по себе не создаёт пользователя.
4. В админке приложения проверьте пользователя, компанию и событие начала пробного периода. Дату и время окончания можно изменить, в том числе кнопкой «5 минут».
5. Создайте пользователя вручную и выдайте ключ через админку; установите нужный срок доступа. Настроенный SMTP отправляет письмо с ключом. Ключ активации одноразовый; после активации пользователь входит в свой аккаунт.
6. Создайте услуги и сотрудников в приложении. Новая запись принимает имя и телефон нового клиента, затем сохраняет клиента и проверяет пересечения в общем календаре.

## Бот на сервере клиента

В приложении можно выбрать размещение у BIZ или экспорт комплекта для собственного сервера. Экспорт содержит отдельные ограниченные полномочия; его нельзя публиковать. В комплекте есть Compose и инструкция. Telegram-токен остаётся на сервере клиента. Там работает транспорт Telegram; компании, записи и проверка конфликтов продолжают обслуживаться API BIZ. Админка показывает состояние такого подключения без Telegram-токена клиента.

Для удалённого сервера клиента нужен доступный HTTPS API. Адрес `127.0.0.1` подходит только для тестирования на этом компьютере. Локальный Compose включает `CH_LOCAL_TEST_MODE=1` для ссылок в тестовых письмах. Для публичного запуска используйте HTTPS, отключите этот флаг, закройте прямой доступ к API и админкам согласно [инструкции](deploy/DOCKER.md). Рабочие базы, серверные ключи и SMTP-настройки переносятся отдельно защищённой резервной копией.

## Проверки

Node.js 24 или новее:

```sh
npm ci --prefix orbit_admin
npm test --prefix orbit_admin
npm ci --prefix ch_landing
npm test --prefix ch_landing
npm ci --prefix landing_admin
npm test --prefix landing_admin
docker compose config --quiet
```

Клиентская защита не делает настольную программу невзламываемой. Сервер проверяет права, срок лицензии, подпись устройства и повторное использование запросов. Подписанное разрешение действует не дольше пяти минут и не дольше лицензии; приложение обновляет его каждую минуту. Повторная пробная регистрация ограничена подтверждённой почтой и ключом устройства. Новое устройство с новой почтой нельзя надёжно связать с прежним человеком без дополнительной проверки личности.
