# Общее локальное окружение LOMVIKO

Корневой `compose.yaml` запускает пять сервисов: API, сайт, админку сайта, админку продукта и веб-приложение.

| Сервис | Адрес на этом компьютере | Проект |
| --- | --- | --- |
| Сайт | http://127.0.0.1:4546 | `website` |
| Админка сайта | http://127.0.0.1:4547 | `platform/web/admin/website.html` |
| Админка продукта | http://127.0.0.1:4548 | `platform/web/admin` |
| Веб-приложение | http://127.0.0.1:4549 | `platform/web/app` |
| Общий API и база | http://127.0.0.1:4545/healthz | `platform/owner` |

API нужен всем трём интерфейсам: он хранит компании, лицензии, контент сайта, почтовые настройки и каталог релизов. Админка приложения использует тот же серверный образ с другой командой запуска; второй раз образ не собирается. Внутри сети Docker сайт и обе админки обращаются к `http://api:4545`.

## Запуск и управление

Из корня репозитория `admin_crm_site`:

```sh
sh 33service/tools/docker.sh start        # собрать образы и запустить, дождаться healthchecks
sh 33service/tools/docker.sh status      # состояние сервисов
sh 33service/tools/docker.sh logs        # журналы всех сервисов
sh 33service/tools/docker.sh stop        # остановить, сохранить данные
sh 33service/tools/docker.sh update      # пересобрать и запустить после изменения исходников
sh 33service/tools/docker.sh credentials # записать данные входа в защищённый локальный файл
```

Также работает `docker compose up -d --build --wait`. Для других портов скопируйте `.env.example` в `.env` и измените значения; Compose автоматически подставит те же порты в разрешённые origin админок и публичный адрес API. Используйте именно `127.0.0.1` в адресах админок: проверка Host и Origin соответствует этим адресам.

Это локальный запуск на данном компьютере. Порты привязаны к `127.0.0.1`. Для публичного HTTPS-развёртывания с доменами используется существующая конфигурация `platform/deploy` и её инструкции; корневой Compose не публикует локальные админки в интернет.

## Вход в админки

На первом запуске API создаёт свой admin secret, ключ издателя и секрет TOTP. `sh 33service/tools/docker.sh credentials` сохраняет admin secret и URI настройки приложения-аутентификатора в `.runtime/admin-access.txt` с правами `600`; каталог имеет права `700` и исключён из Git. Данные не печатаются в журналы сборки и не включаются в образы.

В обеих админках используйте admin secret из первой строки и шестизначный код из аутентификатора, настроенного по URI из второй строки. Для ручного добавления в аутентификатор используется значение параметра `secret` из URI; параметры SHA1, 6 цифр, 30 секунд. Для каждого нового входа нужен новый код: повторное использование кода блокируется общим API. Cookies двух админок имеют разные имена, поэтому обе могут быть открыты в одном браузере одновременно.

Сессии админок хранятся в памяти и после перезапуска требуют нового входа. База, ключи и секреты сохраняются.

## Данные

- `ch-platform_api-data` содержит базу общего сервера, базы компаний и серверные ключи.

Пересборка, `stop` и обычный `down` сохраняют volumes. `docker compose down -v` удаляет их вместе с данными. Новое Docker-окружение использует собственную базу: существующие локальные базы других установок автоматически не импортируются.

## Проверка

```sh
node 33service/tools/docker-check.cjs
```

Проверяются состав Compose, локальные порты, доступность страниц, передача публичных данных API через сайт, реальный вход в обе админки с TOTP и подписью, независимые cookies в одном браузере, права админки сайта и выход из сессий. Проверка не меняет компании и контент, но использует одноразовые коды TOTP; перед повторной проверкой может потребоваться дождаться новых кодов. Исходники серверных проектов проверяются их собственными `npm test`.

Если нужен код для немедленного входа без настройки аутентификатора на этом компьютере, выполните `sh 33service/tools/docker.sh code`. Команда прочитает защищённые данные работающего Docker API, выведет admin secret, свежий шестизначный код и время окончания действия. Уже использованные коды пропускаются; при необходимости команда дождётся следующего допустимого интервала. Для второго входа выполните её снова. Эта локальная команда требует доступа к Docker-серверу и не отключает двухфакторную авторизацию.

## Локальный тест заявок и писем

В локальном compose API получает `CH_LOCAL_TEST_MODE=1`, разрешающий ссылки доступа на `http://127.0.0.1:4546` и API `http://127.0.0.1:4545`. Они открываются на этом же компьютере. Публичное развёртывание не включает этот флаг и требует HTTPS origin. Для запуска API без Docker локальное исключение включается явно: `CH_LOCAL_TEST_MODE=1 npm run server` в platform.

Форма заявки доступна, когда в опубликованном контенте сайта указан контактный email. Она сохраняет заявку, а не создаёт лицензию автоматически. В админке приложения создайте демо для email из заявки, укажите срок (по умолчанию 14 дней); письмо даст ссылку установки пароля и скачивания CRM.
