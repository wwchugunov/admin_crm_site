# Lomviko: SEO-аудит и выполненные изменения

Дата: 29 октября 2026. Область: публичный маркетинговый сайт `lomviko.com`, языковые версии `/` и `/en`, доступ к его ресурсам и исключение технических страниц из индексации. Изменения подготовлены в рабочем каталоге, **на production не опубликованы**. Исходные изменения кеширования и анимаций из предыдущей задачи сохранены.

## 1. Что обнаружено

| Приоритет | Фактическая проблема | Влияние и решение |
| --- | --- | --- |
| P0 | В локальном и production robots.txt задан `Disallow: /public/`, без исключения для `/public/site`. | Блокируется XHR с опубликованным содержимым. Добавлено точное `Allow: /public/site$`, остальные публичные API остаются под прежним запретом. |
| P0 | В исходном HTML отсутствовали возможности, тарифы, FAQ и ряд других основных блоков. | Содержимое зависело от выполнения JS. Существующий рендерер теперь выполняется также на сервере для всех посетителей. |
| P0 | `/en` менял только head и `lang`, сохраняя украинский body до запуска JS. | Язык документа не соответствовал содержимому. Теперь исходный HTML полностью локализован. |
| P0 | Сохранённый язык мог менять `/` на английское содержимое без соответствующего адреса. | Непоследовательные язык и canonical. Язык определяется адресом; переключатель стал обычными HTML-ссылками с сохранением интерактивного переключения. |

| P1 | JSON-LD всегда был украинским, содержал фиксированные цены и FAQ независимо от текущего контента и языка. | Генерируются локализованные Organization, WebSite и SoftwareApplication. Неподдерживаемые текущими данными фиксированные offers/FAQ удалены. |
| P1 | `lastmod` обеих страниц был фиксированным `2026-10-20`, хотя тексты и тарифы редактируются отдельно. | Недостоверные даты удалены; карта сохраняет только два действительных канонических URL и hreflang. |
| P1 | У кабинета, админок и JSON-ответов API не было общего HTTP-запрета индексации. | Добавлен `X-Robots-Tag`; авторизация остаётся основным механизмом защиты. Личные ссылки управления записью и embed-копии также получили noindex. |
| P1 | Lighthouse обнаружил низкий контраст второстепенного текста, включая подвал и подписи в демонстрации. | Скорректирован только цвет второстепенного текста; компоновка, шрифты и основные цвета сохранены. |
| P1 | Google Ads мог конкурировать с первичной отрисовкой. Браузер повторно создавал уже готовую разметку. | Существующий тег загружается после ресурсов страницы в idle-период; очередь событий создаётся сразу. Повторная отрисовка неизменённого HTML исключена. |

На production уже корректно работают HTTP → HTTPS (308), www → основной домен без www (301), `/en/` → `/en` (301), главная и `/en` (200), неизвестная страница (404), gzip. Эти механизмы не заменялись. Проверены прямыми HTTP-запросами. Неавторизованные запросы к приватным API возвращали 401 ещё до изменений.

## 2. Доступ к публичным данным и безопасность

Назначение `/public/site` установлено по `platform/api/public-site.cjs`, маршруту API, браузерным потребителям, тестам и ответу production без авторизации. Ресурс возвращает опубликованные украинские и английские тексты, публичный контакт, видимые анонсы, сведения о опубликованных документах и публичное состояние продукта. Черновики, заявки, база пользователей, пароли и административные ключи в этот ответ не включаются. Тесты отдельно проверяют отсутствие черновиков и контактов заявителей.

Открыт для обхода только точный путь `/public/site`. Соседние пути, произвольные суффиксы и параметры этим исключением не разрешаются; gateway по-прежнему отклоняет параметры у API. JS, CSS, шрифты и изображения доступны. JSON-ответ получает `X-Robots-Tag: noindex`: его можно загрузить для рендеринга страницы, но он не должен становиться отдельным поисковым результатом.

Правило выбирается по наиболее специфичному совпадению. Проверено парсером robots.txt для Googlebot. Ограничения robots.txt **не заменяют контроль доступа** — это соответствует [документации Google о правилах robots.txt](https://developers.google.com/crawling/docs/robots-txt/robots-txt-spec) и [ограничениях robots.txt](https://developers.google.com/search/docs/crawling-indexing/robots/intro).

Серверный рендерер обращается только к настроенному API origin и фиксированному `/public/site`, без cookies, Authorization и клиентских заголовков. В HTML помещается проекция используемых публичных полей; ненужные API-поля и адреса файлов документов не сериализуются. Тексты экранируются; JSON внутри script защищён от закрывающего `</script>`. Это проверено тестами с намеренно опасными строками.

CSP, ограничения origin, подписанные запросы, CORS, rate limits, авторизация, интеграции и операции записи данных не ослаблены. У кабинета и админок добавлен только заголовок индексации. Для обычной страницы компании `/b/<slug>` индексация не отключена; `?visit=…` и `?embed=1` исключены. Перечисление компаний и персональных ссылок в маркетинговый sitemap не добавлялось.

## 3. Рендеринг, метаданные и структура

Существующие словари, шаблоны возможностей, тарифов, сценариев, отраслей и FAQ перенесены из `app.js` в общий `content.js`. Их использует и Node, и браузер. Новый `render.cjs` разбирает существующий HTML через LinkeDOM и вызывает эти же функции. Это серверная отрисовка существующего сайта, без альтернативного содержания для Googlebot и без нового фреймворка.

Опубликованный снимок запрашивается одним совместным запросом для двух языков и кешируется до 30 секунд. Обращение ограничено таймаутом 1,5 секунды и размером 1 MiB. При ошибке, таймауте или некорректном ответе отдаётся полный локализованный резервный HTML; повторная попытка выполняется после короткого интервала. Браузер дополнительно получает актуальный публичный ответ и обновляет страницу только при изменении используемых данных. Реальная регистрация и все операции по-прежнему контролируются API.

В первоначальном ответе доступны H1, основные тексты, возможности, интеграции, сценарии, тарифы, FAQ и ссылки. Страница работает как информационная и без JS; интерактивные примеры и отправка формы требуют JS, для этого состояния предусмотрен контакт по email. Языковые ссылки работают без JS и поддерживают обычное открытие в новой вкладке.

Для `/` и `/en` проверены отдельные title/description, один H1, H2/H3, `lang`, canonical, взаимные hreflang, локализованные OG/Twitter и alt содержательного изображения. Маркетинговые параметры не попадают в canonical и не теряются из-за нового перенаправления. Страница 404 возвращает 404 и noindex. Документы и технические ответы не попадают в sitemap.

Разметка Schema.org содержит только подтверждённые сведения о компании, сайте и веб-приложении. Рейтинги, отзывы, достижения и цены не выдумывались. BreadcrumbList не добавлен: отдельной навигации «хлебные крошки» нет. JSON-LD проверен локально на синтаксис, типы, язык, URL и отсутствие неподтверждённых offers/ratings. Это **не равно внешней проверке Schema.org или Google Rich Results Test**. После публикации следует проверить URL этими инструментами; соответствие типу SoftwareApplication само по себе не гарантирует расширенный результат. См. [рекомендации Google по проверке генерируемой разметки](https://developers.google.com/search/docs/appearance/structured-data/generate-structured-data-with-javascript).

## 4. Семантика и контент

Проведена актуальная поисковая проверка формулировок из ТЗ. Широкие запросы о CRM смешивают товарные продажи, воронки и услуги: это видно, например, по предложениям [SalesDrive](https://salesdrive.ua/crm/). Запросы об онлайн-записи приводят к специализированным предложениям, например [SUDUS·TEAM](https://sudus.team/services/crm/online-booking) и [Bookka](https://bookka.pro/uk). Это качественная оценка намерения и наличия конкурентов, **не измерение частотности или Keyword Difficulty**. Доступа к Keyword Planner, Serpstat/Ahrefs и статистике Search Console нет; численные объёмы спроса и позиции не заявляются.

| Страница / блок | Основная тема | Дополнительные формулировки |
| --- | --- | --- |
| `/` | CRM для сфери послуг, онлайн-запис клієнтів | CRM для малого бізнесу, програма для запису клієнтів |
| `/en` | Service business CRM, online appointment booking | Английская версия того же продукта; отдельное украинское семантическое ядро ей не назначается |
| `#features`, `#owner` | Расписание, клиентская база, финансы | Система управління клієнтами, автоматизація малого бізнесу — только в контексте реальных функций |
| `#page`, `#launch` | Страница записи и порядок запуска | Онлайн-запис клієнтів, програма для запису клієнтів |
| `#business` | Применение в салонах, клиниках, студиях и услугах | Отраслевые формулировки без создания копий главной |

Украинские title, description и вводный текст уточняют назначение продукта и малый бизнес в услугах. Цены и временные акции убраны из поисковых метаданных, чтобы не закреплять устаревающие обещания в сниппете. Тарифные карточки используют существующее состояние продукта. Ключевые слова не распределялись по новым пустым URL. Пересечение языковых версий оформлено hreflang, а не одинаковым canonical для разных языков.

Новые посадочные страницы не созданы. Для будущей страницы о салонах нужны собственный рабочий сценарий, настройка команды, расписание и демонстрация записи; для онлайн-записи — подробный путь клиента, QR/ссылка и реальные ограничения; для аналитики — подтверждённые отчёты и пояснение расчётов. Общая страница «CRM для предприятий сферы услуг» сейчас пересекалась бы с главной, поэтому отдельно её создавать преждевременно.

Включены проверки защиты API, входа, админок, публикации, онлайн-записи, ограничений запросов, SSR, отказов API, экранирования, индексации и кеширования. Установка по lockfile через `npm ci --prefix website --ignore-scripts` прошла. Проверка лицензий прошла; `npm audit --prefix website --omit=dev` сообщил 0 известных уязвимостей. `docker compose config --quiet` и `git diff --check` прошли.

Браузерные проверки Chrome выполнены на 320, 390, 768 и 1440 px: нет горизонтальной прокрутки и ошибок JavaScript; работают переключение языка, клавиатурная навигация, вкладки, демо-бот, калькулятор и диалог заявки. Проверена английская страница без JavaScript. Ответы обычному посетителю и Googlebot идентичны. Отдельный тест подтверждает сохранение конверсии в очереди до загрузки отложенного Google Ads.

Разброс большой, поэтому нельзя приписывать все различия изменениям кода. В одном мобильном запуске LCP остался выше 2,5 с. Best Practices снижен существующими third-party cookie/Issues Google Ads; трекер не удалён и новый сервис не добавлен.

SSR увеличил объём передаваемого HTML: медиана общего трафика локального мобильного прогона изменилась примерно с 429 до 470 KB без gzip. Это осознанный обмен на доступность содержимого в исходном ответе, а не уменьшение всех ресурсов. Клиентская библиотека DOM не добавлена: LinkeDOM работает только в Node. Суммарный собственный JS остаётся примерно 103 KB без сжатия. Удаление нужных интерактивных функций ради оценки не проводилось.

Изображение интерфейса уже имеет размеры, lazy loading и async decoding; не перекодировалось без доказанной необходимости. Шрифты локальные, с unicode-range и font-display:swap. Критичный preload соответствует языку. Статические файлы сохраняют ETag и корректную ревалидацию; неизменённые HTML/JS/CSS могут возвращаться как 304 без тела. Сжатие на production отдельно подтверждено HTTP-ответом gzip.

**INP и реальные пользовательские LCP/CLS на 75-м процентиле не измерены. TBT не является INP.** Пользовательских данных CrUX/Search Console в распоряжении нет. Целевые пороги следует оценивать по полевым данным отдельно, как описано в [Web Vitals](https://web.dev/articles/vitals).

## 7. Ограничения и действия владельца

Docker daemon недоступен в рабочей среде, поэтому **Docker-образ не собирался и контейнерный прогон не выполнен**. Проверены установка зависимостей, непосредственный запуск Node, HTTP, браузер и Compose-конфигурация. В проекте нет отдельной сборки фронтенда: это HTML/CSS/JS и Node. Финальный контейнер нужно собрать при обычном развёртывании по [PRODUCTION.md](PRODUCTION.md); сайт теперь требует установки зависимостей из `website/package-lock.json`.

Доступа к Google Search Console, CrUX, Google Ads account и подтверждённым результатам отправки конверсий нет. Структурированные данные не проверялись внешними валидаторами на опубликованном новом URL. Реальная индексация, rich results, полнота истории конверсий и полевые Core Web Vitals не заявляются проверенными. Роуты компаний `/b/*` не перечислялись и не наполнялись искусственным содержимым; их полноценное отраслевое продвижение — отдельная работа с разрешёнными данными компаний.

После публикации:

1. Проверить `https://lomviko.com/robots.txt`, точное исключение `/public/site` и `https://lomviko.com/sitemap.xml` на production. Кеш роботов может обновиться не сразу.
2. В доменном свойстве Search Console отправить или повторно отправить sitemap. В нём должны быть только `/` и `/en`.
3. Через «Проверка URL → Проверить опубликованный URL» проверить обе страницы. В просмотре HTML/ресурсов убедиться, что доступны тексты, тарифы и FAQ, `/public/site` больше не заблокирован, JS/CSS/шрифты загружаются. Проверить заявленный и выбранный Google canonical.
4. Запросить индексирование `/` и `/en`. В отчёте с прежней ошибкой запустить проверку исправления, если интерфейс её предлагает. Не отправлять API и технические страницы на индексирование.
5. Проверить оба URL в [Schema.org Validator](https://validator.schema.org/) и [Google Rich Results Test](https://search.google.com/test/rich-results). Отсутствие права на расширенный результат не исправлять вымышленными отзывами или рейтингом.
