# Первый запуск lomviko.com

Рабочая схема: на VPS — сайт, две админки, API и каталог установщиков; разработка CRM — на любом ПК из исходников с подключением к https://api.lomviko.com. SSH нужен для обслуживания серверной части, а не для каждой правки CRM.

Сначала проверки и push обоих репозиториев в GitHub. Затем `npm run prepare:deployment` из корня этого репозитория создаёт архив из чистого коммита Git и JSON с commit/SHA-256 в `.runtime`. Не используйте прежний архив общего рабочего пространства: он не содержит этих исправлений. Архив исключает локальные данные и ключи.

После переноса архива на VPS:

```sh
mkdir -p /opt/biz
tar -xzf /root/biz-platform-COMMIT.tar.gz -C /opt/biz
cd /opt/biz/admin_crm_site/orbit_admin
cp deploy/lomviko.env.example deploy/.env
chmod 600 deploy/.env
sh deploy/manage.sh start
```

`mkdir` создаёт папку приложения. `tar` распаковывает исходники, `cd` переходит к серверному проекту. `cp` создаёт конфигурацию доменов для первого запуска (при обновлении существующую `.env` не заменяйте). `chmod` закрывает доступ к конфигурации другим пользователям. `manage.sh start` проверяет Compose, собирает образы, проверяет отсутствие публичных внутренних портов, готовит каталог установщиков и запускает сервисы с healthchecks.

DNS A-записи lomviko.com, www и поддоменов должны указывать на 185.25.117.161. Если IPv6 не настраивали, не добавляйте AAAA. На firewall провайдера и ОС нужны входящие TCP 80/443 и SSH. HTTPS выпускает Caddy; www перенаправляется на основной домен. Порты 4545–4548 наружу не открываются. На AlmaLinux оставьте SELinux включённым: bind mounts имеют метки `z` (общий каталог релизов) и `Z` (конфигурация Caddy).

Для проверки состояния:

```sh
sh deploy/manage.sh status
curl --fail https://api.lomviko.com/healthz
curl --fail https://api.lomviko.com/v1/info
```

`status` показывает состояние контейнеров, `curl` проверяет публичный HTTPS API. `/v1/info` возвращает только публичный ключ. SHA-256 ключа можно получить внутри контейнера:

```sh
cd deploy
docker compose --env-file .env -f compose.yaml -f compose.website.yaml exec -T orbit node -e "const fs=require('node:fs'),c=require('node:crypto');console.log(c.createHash('sha256').update(c.createPublicKey(fs.readFileSync('/data/publisher-public.pem')).export({type:'spki',format:'der'})).digest('hex'))"
```

Пользовательские базы, admin secret, секрет TOTP и приватный ключ создаются на VPS в постоянном Docker volume. Локальные тестовые данные туда не переносятся. Старый локальный `.runtime/admin-access.txt` не является доступом к новому серверу. Для первого входа выполните на доверенном SSH-терминале:

```sh
docker compose --env-file .env -f compose.yaml -f compose.website.yaml exec orbit node tools/admin-setup.cjs /data --show-credentials
```

Команда показывает реальные секреты. Сохраните их в менеджер паролей и добавьте TOTP в аутентификатор; не отправляйте вывод в чат или Git. Адреса: https://admin.lomviko.com и https://site-admin.lomviko.com. Для каждого входа нужен новый TOTP.

Для отдельной компании владельца:

```sh
docker compose --env-file .env -f compose.yaml -f compose.website.yaml exec -T orbit node tools/provision-owner.cjs /data OWNER_EMAIL
```

Замените OWNER_EMAIL своей почтой. Команда создаёт отдельную тестовую компанию, активный бессрочный аккаунт и лимит 10 устройств. Она не отправляет почту и не печатает пароль. Повторный запуск не сбрасывает пароль, не добавляет новую компанию и отказывается менять существующий обычный аккаунт. Задайте пароль через админку. Бессрочность также доступна в форме редактирования аккаунта; клиент продолжает проверять короткие подписанные допуски и блокировку.

На ПК: `npm ci`, `npm run setup:production`, сверить SHA-256 ключа, `npm start`, войти личным аккаунтом. При следующем изменении CRM нужен только перезапуск приложения. Установщики собираются отдельно перед выпуском с production URL и тем же публичным ключом. Не загружайте local-test сборки в публичный каталог.

В админке задайте SMTP (для порта 587 используется STARTTLS), email отправителя/владельца, публичные URL сайта/API и проверьте письмо. Без SMTP самостоятельная регистрация по email намеренно недоступна; личный аккаунт с паролем работает. Google OAuth, настоящий Telegram и права на бренд требуют собственной настройки/проверки. Зафиксируйте результат реальной регистрации после настройки SMTP.

Перед обновлением существующего сервера сделайте согласованную резервную копию базы с WAL, ключей и releases вне VPS. Не удаляйте volumes, не меняйте ключ издателя, не используйте `down -v`. Сохранение данных важнее удобства переустановки. Проверяйте восстановление резервной копии; snapshot провайдера не заменяет независимую копию.
